From manual exports to an automatic data sync

The workbook QA receives stays the same in every step: only the way the PAS-X rows arrive changes.

What the job is

Move one read-only query result — a few thousand rows per product per year — from the MES Oracle database to wherever QA builds the APQR. The volume is tiny. The real bottleneck is permission: a read-only database account and a network path to the database. Every automatic option, free or paid, needs exactly that approval.

Recommended order

  1. Now: option A — no approvals beyond what exists.
  2. Ask IT for the read-only MES database account and the network path. This unblocks everything below.
  3. Option B with that account: free, on-prem, the data is current daily.
  4. Fabric when the company wants one data platform anyway (several sites, LIMS/QMS/ERP next to MES, dashboards, continued process verification). For the APQR alone it adds a monthly cost, a cloud copy of GMP data and more to validate, without removing step 2.

The Fabric path

QAworkbook files; optional Power BI on the curated tables
  1. Install the on-premises data gateway (standard mode) on a plant server that reaches the database.
  2. Create an Oracle connection on the gateway with the read-only account.
  3. Create a workspace and a Lakehouse.
  4. Pipeline: Copy activity with the rolling-window query (material list as a pipeline parameter) and an extra LOAD_TS column = trigger time, appending to a raw table; then a Notebook activity; schedule nightly.
  5. Notebook: keeps the newest load of each batch (a corrected re-run supersedes older rows), builds the same workbook as this page, and writes curated value and summary tables for Power BI.
  6. Qualification run: one material, a closed period — compare the Fabric workbook cell by cell with this page's output for the same export.

The query (rolling-window form), the notebook and the detailed checklist are in the internal AdigiPQR package (fabric/), not on this public page.

Beyond

  1. More sources in the same Lakehouse: LIMS results, QMS (deviations, CAPA, change control), ERP (release, market) — the APQR sections that are manual today fill themselves.
  2. Continued process verification: the nightly summary table is a CPV dashboard — Cpk and trend signals per CPP as batches are made, not once a year.
  3. Scanned BMR values: records accepted on the scan tab (CSV export) join the same tables, so printout CPPs trend with the MES data.
  4. Validation: keep query and notebook under version control as the controlled source; treat the sync as GAMP 5 configured software with its own IQ/OQ.
