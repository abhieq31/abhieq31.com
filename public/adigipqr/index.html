Guides

Ways to run it, and the path to an automatic data sync.

1 · This page (online or offline)

Everything runs in the browser. Offline: unzip the offline copy (link under "How?") on a PC and double-click index.html for the APQR sheet; for reading scans run start_web_app.bat (a local web server on 127.0.0.1, needs Python).

2 · Plant portal (shared store)

start_portal.bat on one plant server: the MES team loads exports once, QA picks a material and dates and downloads. Adds server-side BMR scan reading (RapidOCR) and an optional read-only nightly pull from PAS-X.

3 · Command line

python python/apqr_pivot.py export.csv or drag the export onto build_apqr.bat. Same workbook.

4 · Automatic data sync

Step-by-step in Data sync and Microsoft Fabric: scheduled read-only pull first (no licence, data stays on-prem), Fabric pipeline + Lakehouse when the company wants one data platform.

Which parameters are CPPs

Every parameter is labelled CPP, CPP? or CQA with its reason: QA's CPP list for the product (Options) first, then the PAS-X MBR criticality flag, then what is typical for the unit operation (to be confirmed by QA). Labels never change a value.

QA's official workbook

Drop QA's own workbook in Fill QA's official workbook: new batches go into BMR detail, QA's formulas carry them to the other sheets, empty cells are filled from PAS-X, nothing QA typed is overwritten, yellow (LIMS / Tantra) columns can be left for QA, and a report sheet traces every value.

Two kinds of request

Material + period ("all batches of material X from Y to Z") or Batch numbers ("with respect to each batch no.", material optional). The SQL query takes the same two forms.

Proving the workbook

APQR sheet → Check against QA's manual workbook: drop QA's hand-made Excel for the same batches; every value QA typed is marked MATCH / MISMATCH / NOT_IN_MES. Try it with Load example data and Use the example QA workbook.
